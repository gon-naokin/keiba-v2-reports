# keiba-v2-reports

v2序列モデルによる競馬予想サマリーの公開ページです。

- 公開ページ: GitHub Pages
  - `index.html` = 最新日の予想サマリー（サイトの入口）
  - `index_<MMDD>.html` / `analysis_<MMDD>.html` = 開催期間（土・日・月）の各日の予想サマリーと解析ビジュアル
  - `results.html` = 結果まとめ（日付タブで開催期間の各日を切替）
  - `analysis.html` = 最新日の解析ビジュアルへの転送ページ（平文・転送先のファイル名のみ）
  - `days.json` = 開催期間の日付一覧（平文・日付と場名のみ。各ページの「開催日」ナビが読む）
- **閲覧にはパスワードが必要です**（StatiCrypt による AES-256 クライアントサイド暗号化）
- 現在の掲載内容: 2026年11月21日（福島・京都）・11月22日（東京・京都）・11月23日（福島・東京）
- 本ページはツール出力の機械整理であり、的中・回収を保証するものではありません

## 更新方法

平文ソース（`src/`、リポジトリには含まれません）を作り、StatiCrypt で暗号化して
リポジトリ直下の同名ファイルを差し替え、main に push すると反映されます。

```bash
python src/tools/extract_analysis.py 2026-11-23        # yosou_tool.html と jvlink.sqlite から JSON を抽出
python src/tools/build_analysis.py 2026-11-23          # analysis_template.html -> src/analysis_1123.html
python src/tools/build_results_page.py 2026-11-23 2026-11-22 2026-11-21   # results_template.html -> src/results.html
# 予想サマリーを src/index_1123.html として用意したうえで:
python src/tools/build_site.py 2026-11-21 2026-11-22 2026-11-23   # days.json・ナビ・index.html・転送ページ
cd src
npx -y staticrypt@3 index.html index_1123.html analysis_1123.html results.html -d .. -p "<閲覧用パスワード>" --remember 30
```

- `build_site.py` には開催期間の全日付を渡します。新しい開催の初日は、その日だけを渡して
  `--prune` を付けると、前の開催の公開ファイルを削除します
- 古い日のページは `days.json` を読んでナビを作るので、日を足しても作り直す必要はありません
  （暗号化するのは、その日に変わったページだけで足ります）。テンプレートを変えたときは、
  開催期間の全日を `build_analysis.py` に渡して作り直します
- `build_results_page.py` は指定した日付（先頭が初期表示）の予想を埋め込みます。
  結果は公開後にページ側が `results_<MMDD>.json` を取得して突き合わせるため、
  結果が確定するたびにページを作り直す必要はありません
- 公開済みの日の `analysis_<MMDD>.json` に新しい項目だけ足したいときは
  `extract_analysis.py <日付> --augment` を使います（スコアと順位は公開時のまま変えません）

## レース結果の反映

- 手動: 解析ページ各レースの「結果の記録」に1〜3着の馬番を入力して保存（ブラウザ保存）
- 自動: `results_<MMDD>.json` を push すると、解析ページの「公式結果を一括取得」ボタンで
  全レースに反映されます。結果まとめページは開くだけで自動取得し、未確定がある間は5分ごとに再取得します

```bash
python src/tools/make_results.py 2026-11-22   # jvlink.sqlite に確定成績があるとき
git add results_1122.json
git commit -m "data: 結果更新"
git push
```

JRA-VAN の蓄積系データは確定成績の配信が開催の数日後になるため、当日・翌日に結果を載せるときは
JRA公式サイトのレース結果ページから同じ形式の JSON を作ります（`src/tools/jra_web/`）。
`make_results.py` は、jvlink に成績がまだ無い間は既存の結果ファイルを空で上書きしません。

`results_*.json` は公開ファイルです（JRAの公式確定結果のみで、予想内容は含まれません）。
レースキーごとに 1〜3着の馬番（`"1"`/`"2"`/`"3"`）、全馬の着順・人気・単勝オッズ（`ord`）、
式別の払戻（`pay`）を持ちます。

## ペースマップの着順線

解析ページで結果を記録すると、前走ペースマップに 1〜3着馬を通る最小二乗直線（着順線）を描き、
式 `y = ax + b`（x=前走PCI・y=前走脚質度）をコース署名の式と並べて表示します。

## ラップ経緯の「加速」印

解析ページの「ラップ経緯」では、ラスト2Fが加速ラップ（最終1Fが直前の1Fより速い）だった走に
「加速」印を付け、折れ線の該当区間を橙の太線で示します（着順は問いません）。
さらに前の1Fから続けて加速している場合は 2区間ぶんを塗ります。
`⤴`（勝利かつ終い加速質ラップ＝モデルのシグナル定義）とは別の印です。

## ラップ経緯の詳細分析（想定PCIに近いレースへの絞り込み）

「詳細分析を開く」を押すと、比較対象を中心PCI±幅に入るレースだけに絞り込みます。

- 中心PCIの既定は今走の想定PCI（出走馬の前走PCIの中央値）。「前走PCI平均」ボタンとスライダーで変更できます
- 幅は ±0.5 / ±1.0 / ±1.5 / ±2.0 / ±3.0 から選びます
- コースの過去レース（直近120レース）: 該当レースの決まり手・平均レース脚質度・上がり3F・
  ラスト2F加速ラップ率・荒れ率をコース全体と比較し、平均ラップを重ねて表示します。該当レースの一覧つき
- 出走馬の近5走: レースPCIが範囲外の走を薄く表示します。「類似ペース」は、今走と同じ芝ダで
  範囲内だった過去走（直近30走まで）の [1着-2着-3着-着外] と複勝率です

脚質度の読み方:

- 馬の脚質度 = PCI3 − 馬個別PCI（正=前で運ぶ・負=後ろから）
- レース脚質度 = PCI3 − レースPCI（0未満=先行有利・0〜1.4=中立・1.4超=差し有利の流れ）
- コース平均脚質度 = 出走全馬の脚質度の平均（正=差し寄り・負=先行寄り）
